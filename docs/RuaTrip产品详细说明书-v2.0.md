# RuaTrip（Rua途）产品详细说明书

版本 v2.0 ｜ 平台：移动端 App（iOS / Android）

---

## 一、产品总述

**一句话定位**：给无法养真宠物的人，一个可以用 3D 真实感形象云养、能真心聊天、能一起旅行打卡、还能自动帮你做手账的毛绒搭子。

**目标用户**
- 有养宠障碍的都市年轻人：猫毛狗毛过敏、租房禁宠、频繁出差、作息不规律
- 经历过宠物离世、希望延续陪伴的用户
- 喜欢旅行创作、但缺趣味素材与文案灵感的年轻女性

**核心价值主张**
1. **门槛归零**：不需要真实饲养条件，也能拥有一只"命中注定"的宠物
2. **真实感陪伴**：3D 形象、可换装、可换场景、可互动，不是静态贴纸
3. **关系会生长**：好感度、性格、记忆随相处累积，宠物越用越"像它"
4. **输出即内容**：旅行照片合成、手账、朋友圈排版一次生成

**与现有产品的差异**
市面上的虚拟宠物产品大多停留在 2D 立绘或像素养成；宠物复原类产品止步于"生成一张图"。RuaTrip 的差异点是把**3D 真实感形象 + 长期关系系统 + 旅行场景**三件事串成一条链，让宠物真正"参与生活"。

## 二、整体实现可能性分析

### 2.1 可行性总览

| 模块 | 可行性 | 关键依赖 | 主要风险 |
| --- | --- | --- | --- |
| 偏好问卷与画像 | 高 | 自研规则引擎 | 冷启动数据不足 |
| 3D 形象生成 | 高 | 第三方 3D 生成 API | 单次生成成本与耗时 |
| 自动绑定骨骼 | 中高 | 动物类自动绑定服务 | 非猫狗物种绑定失败率 |
| 服装更换 | 高 | 模块化挂点 + 贴图替换 | 服装与体型适配 |
| 背景切换 | 高 | 环境贴图 / 场景资产 | 移动端性能 |
| 互动动画 | 高 | 动画库 + 状态机 | 动作自然度 |
| 真心话小屋（LLM 对话） | 高 | 成熟大模型 API | 人设漂移、内容安全 |
| 语音对话 | 中高 | 语音合成 + 语音识别 | 中文情绪表现、延迟 |
| 旅行照片合成 | 高 | 图像合成 + 角色锁定 | 形象一致性 |
| 已逝宠物复原 | 中高 | 图生 3D / 图生图 | 情感伦理与预期管理 |
| 手账与朋友圈排版 | 高 | 模板引擎 + 文案生成 | 同质化 |

**总体结论**：产品整体可实现，且不需要自研底层模型——所有关键能力都有成熟的第三方接口。真正的难点不在"能不能做"，而在**成本控制、移动端性能、以及形象一致性**这三处工程细节。

### 2.2 技术可行性拆解

**① 偏好数据 → 形象参数**
完全可控。问卷答案归一化为一个多维偏好向量（物种倾向、体型、毛感、配色偏好、性格标签），再由规则引擎映射成 3D 生成提示词与参数。这部分是纯业务逻辑，无技术风险。

**② 3D 形象生成**
成熟。文字/图片转 3D 已有多家商业 API 提供稳定服务，输出可直接带 PBR 贴图。单次生成成本目前在人民币几元的量级，耗时数十秒到数分钟，属于**异步任务**而非实时请求。

**③ 自动绑定骨骼与动画**
这是最需要谨慎评估的一环。市面上自动绑定服务对人形支持最好，对**兽类、鸟类、小型宠物**的骨架识别准确率参差不齐。建议优先选用专门做"任意动物自动绑定"的服务，并为冷门物种准备兜底的通用骨架模板。

**④ 服装更换**
推荐"模块化挂点"方案：宠物模型预设若干挂点（脖子、背部、头部），服装是独立小模型 + 材质。这样一套服装不需要为每只宠物重新生成，只需做尺寸缩放与穿模校正。

**⑤ 背景切换**
技术简单，用环境贴图或低成本场景资产即可。真正要控制的是移动端的内存与帧率——建议背景做**预渲染图片 + 轻量动态元素**的混合方案，而不是完整 3D 场景。

**⑥ 真心话小屋**
技术链路完全成熟：性格档案卡 → 自动拼装系统提示词 → 调用大模型 → 返回文本 → 语音合成。难点是**人设一致性**与**内容安全**，属于提示词工程与运营问题，不是技术瓶颈。

**⑦ 已逝宠物复原**
图生 3D 目前可以做到"毛色、花纹、体型大致相似"的毛绒化复刻，但**无法做到一模一样**。这一点必须在产品层面对用户做明确预期管理，否则会造成二次情感伤害。

### 2.3 产品与市场可行性

- 养宠障碍人群规模真实存在，且长期被忽略：过敏、租房、出差三大现实约束短期内不会消失
- 情绪消费意愿已被验证，用户愿意为"宠物的情绪健康"付费
- 云养宠已被广泛接受为真实需求，用户教育成本低
- 风险在于：虚拟陪伴产品的**留存**普遍偏低，用户新鲜感消退后容易流失。因此"关系会生长"的机制设计（好感度、记忆、成长）是留存的关键，而不是形象精度

### 2.4 商业化可行性

| 收入来源 | 说明 | 预估定位 |
| --- | --- | --- |
| 订阅会员 | 更多生成次数、高级场景、手账模板、形象精修 | 主力收入 |
| 虚拟商品 | 服装、配件、限定皮肤 | 高毛利补充 |
| 情感服务 | 已逝宠物复原精修（一次性付费） | 高客单价，低频 |
| 旅行联名 | 与景区/酒店/航司的城市限定内容合作 | 中长期 |

### 2.5 关键风险清单

1. **形象一致性风险**：同一只宠物在旅行合成、动画、手账中外观漂移 → 必须建立"资产母版"机制
2. **成本风险**：3D 生成按次计费，如果每次互动都重新生成会迅速失控 → 生成必须一次性，之后全部复用
3. **性能风险**：中低端手机上实时 3D 会卡顿掉帧 → 分级降级策略
4. **情感伦理风险**：已逝宠物复原可能引发过度依恋或二次悲伤 → 需要专门的安全设计
5. **内容安全风险**：大模型可能产出不符合人设或不当内容 → 双层过滤
6. **版权风险**：用户上传照片的授权与二次生成边界需明确
7. **未成年人风险**：低价虚拟商品易诱导消费 → 需家长验证与消费限额

## 三、优化建议

### 3.1 产品层面

1. **首日必须交付完整体验**。新用户没有老照片、没有旅行记录，如果第一屏就是空状态，留存会崩。建议新用户完成问卷后立刻获得：一只宠物 + 一段由系统预置的"虚拟初次旅行"，让用户当天就能走完"生成 → 互动 → 打卡 → 手账"完整链路。
2. **好感度不能是单向数值**。只涨不掉会变成无意义的进度条。建议引入"想念值"——长时间不登录宠物会表达小情绪，回来后有"重逢"动画，让关系有双向感。
3. **不要把已逝宠物复原放在主入口**。它情感分量太重，适合"主动寻找"而非"被推销"。放在一个需要用户自己找到的安静角落，效果反而更好。
4. **宠物性格要有"缺点"**。完美的宠物不好玩。傲娇、怕水、贪吃、起床气这类小毛病才是让人记住的地方。
5. **旅行不要只做打卡**。打卡是动作，不是内容。真正的价值是"宠物陪你去过哪里、发生了什么"，需要剧情和记忆承载。

### 3.2 技术层面

1. **建立"宠物资产母版"体系**。每只宠物生成一次，作为唯一的几何与材质母版，后续所有场景（旅行合成、手账、动画、换装）都从母版派生，禁止重新生成。这是形象一致性的根本解法。
2. **生成流程全部异步化**。首次生成时用"孵化"动画掩盖等待，配合进度反馈与通知，让等待本身成为体验的一部分。
3. **服装走"贴图 + 挂点"而非"独立模型"**。可把资产量降低一个数量级，换装也能实时生效。
4. **分级渲染策略**。高端机走实时 3D；中端机降低面数与特效；低端机自动降级为预渲染视频序列。用户感知差异不大，但可用性覆盖全机型。
5. **对话做双层缓存**。常用互动（问候、喂食反馈）走本地预设池，避免每次调用大模型；只有自由对话才走模型接口。成本可下降大半。
6. **性格档案卡模板化**。每只宠物生成一张结构化人格卡（品种、性格、口头禅、喜好、禁忌话题、说话节奏），系统提示词由卡片自动拼装，保证人设不漂移。

### 3.3 体验层面

1. 互动反馈的**延迟比精度更重要**。点击后 100ms 内有反应，比动作精细但延迟 1 秒体验好得多。
2. 动画要有**呼吸感**。待机状态下宠物也应有轻微起伏、眨眼、尾巴摆动，这是"活着"的关键感知。
3. **声音是真实感的放大器**。同样的画面，配上合适的脚步声、呼噜声、哈欠声，沉浸感会成倍提升。
4. 换场景不只是换背景，**光影方向要跟着变**，否则宠物会像贴上去的。

### 3.4 伦理与安全层面

1. 已逝宠物复原区需明确提示"这是基于照片生成的陪伴形象，不是它本人"。
2. 当检测到用户连续高强度使用（长时间停留、频繁提及离世情绪）时，轻量提示休息与支持渠道。
3. 大模型输出做前置过滤（人设外话题、自我认知类问题、医疗建议）与后置审核。
4. 用户上传的照片需明确授权范围与删除通道。

## 四、3D 宠物形象生成与驱动方案

### 4.1 端到端技术链路

```
偏好问卷 / 用户画像
        ↓
偏好向量（物种·体型·毛感·配色·性格）
        ↓
3D 生成 API ──→ 几何 + PBR 贴图
        ↓
自动绑定骨骼 API ──→ 可驱动骨架
        ↓
动画库 + 状态机 ──→ 待机/互动/情绪动作
        ↓
实时渲染层（Web 或引擎）──→ 换装 · 换场景 · 交互
        ↓
LLM 对话引擎 + 语音合成 ──→ 真心话小屋
```

### 4.2 3D 生成模型 API 推荐

| 服务 | 核心能力 | 适配环节 | 推荐理由 |
| --- | --- | --- | --- |
| Tripo AI | 文/图生 3D、贴图、自动绑定、动画、格式转换 | 主力生成 | 接口完整、有官方开放平台、单次成本低，可一次调用走完全链路 |
| Meshy AI | 文/图生 3D、PBR 贴图、自动绑定与动画 | 主力生成 | 工程成熟度高、有企业级合规认证，适合量产与规模化调用 |
| Hyper3D Rodin（Deemos） | 高精度几何生成 | 旗舰形象 | 几何质量出色，适合生成主力宠物与限定稀有物种 |
| 腾讯混元 3D | 开源版可本地部署 + 托管引擎 | 自建与微调 | 开源版本可私有部署，长期成本可控，适合需要深度定制的阶段 |
| CSM.ai / Kaedim | 游戏级可用资产 | 场景物件 | 适合生成服装、道具、场景资产 |
| Luma AI Genie | 快速概念生成 | 原型验证 | 出图快，适合早期美术探索 |

**选型建议**：主力链路选 Tripo 或 Meshy（链路完整、成本可控），旗舰形象用 Rodin 提升质感，长期自建用混元开源版摊薄成本。不建议只押一家，接口层要做适配抽象，便于随时切换。

### 4.3 自动绑定骨骼与动画 API

| 服务 | 能力 | 说明 |
| --- | --- | --- |
| Anything World | 任意 3D 模型的自动绑定 + 动物动画库 | 关键推荐。专门面向非人形对象，覆盖大量动物种类，正好匹配"宠物类型不限于猫狗"的需求 |
| Mixamo（Adobe） | 自动绑定 + 免费动画库 | 人形为主，可复用于直立姿态的宠物或拟人化动作 |
| DeepMotion Animate 3D | 视频动作捕捉 | 可用于批量生产宠物动作素材 |
| Mesh2Motion | 开源自动绑定与动画 | 免费替代方案，适合自建 |
| Tripo / Meshy 内置绑定 | 生成后直接输出可动模型 | 省一条链路，适合做 MVP |

**重点提示**：宠物物种一旦超出猫狗，自动绑定的失败率会明显上升。建议为**稀有物种**准备一套通用四足骨架模板作为兜底，绑定失败时自动套用，保证体验不中断。

### 4.4 实时渲染与播放层

| 方案 | 适用场景 | 说明 |
| --- | --- | --- |
| Three.js + React Three Fiber | Web / 混合式 App | 上手快、生态好，配合 Drei 可快速做出灯光、材质、环境效果，适合绝大多数场景 |
| Unity + 移动端管线 | 原生 App 重度体验 | 动画系统与性能优化能力更强，适合实时 3D 要求高的版本 |
| Unreal + 云端推流 | 极致画质 | 画质最优但成本高，仅适合少量旗舰形象演示 |

**推荐起点**：Three.js 体系。开发效率高、可复用现有前端团队，移动端性能通过面数控制、贴图压缩、多级细节、按需加载完全可以达到可接受水平。

### 4.5 对话与语音 API

**对话层**

| 方案 | 特点 |
| --- | --- |
| Convai | 专为 3D 虚拟角色设计，具备空间感知与动作联动，支持接入自定义大模型 |
| Inworld AI | 角色人格与情绪引擎，人设稳定性好 |
| NVIDIA ACE | 技术套件，生态偏重度开发 |
| 自研组合（推荐） | 成熟大模型 + 自建性格档案卡 + 本地预设池，成本可控、人设最好把控 |

**语音层**

| 环节 | 推荐 |
| --- | --- |
| 语音合成 | MiniMax（中文情感表现佳）、ElevenLabs（准确率与速度优秀）、Fish Audio（性价比高） |
| 语音识别 | 主流中文语音识别服务均可，重点看方言与口音容错 |

### 4.6 两套推荐组合

**组合 A — 快速上线（MVP 首选）**
Tripo API 生成形象 → Tripo 内置绑定 → Three.js 渲染 → 预设动画状态机 → 自研性格提示词 + 通用大模型 → MiniMax 语音合成

优点：链路短、可快速验证、成本低。缺点：动作库有限，自由度一般。

**组合 B — 高保真旗舰（第二阶段）**
Rodin / 混元生成主形象 → Anything World 动物绑定 → Unity 渲染 → Convai 驱动对话与动作联动 → ElevenLabs 语音

优点：真实感强、物种覆盖广、动作自然。缺点：成本与开发量显著上升。

### 4.7 移动端性能与降级策略

| 层级 | 策略 |
| --- | --- |
| 模型控制 | 限制面数上限，导出前做减面 |
| 贴图 | 压缩格式，按需分级加载 |
| 环境 | 背景优先用预渲染图 + 轻量动态元素，不做完整 3D 场景 |
| 动画 | 常用动作预烘焙，避免实时解算 |
| 降级 | 低端机自动切换为预渲染视频序列，功能不缺失 |
| 加载 | 首次生成后本地缓存资产，后续秒开 |

## 五、偏好数据采集与用户画像

### 5.1 问卷设计

控制在 8-10 题，3 分钟内完成，题目要有趣、不枯燥。建议维度：

| 维度 | 示例问题 | 影响参数 |
| --- | --- | --- |
| 物种倾向 | 如果它能说话，你觉得会是哪种小动物？ | 生成物种 |
| 体型偏好 | 你想要抱得住的，还是跟得上的？ | 体型与比例 |
| 毛感偏好 | 想要蓬松的、顺滑的，还是短毛扎手的？ | 材质与渲染参数 |
| 配色偏好 | 从一组色卡里挑三个 | 毛色与花纹 |
| 性格期待 | 粘人的 / 高冷的 / 疯疯的 / 老成的 | 行为与对话人格 |
| 相处节奏 | 你喜欢每天黏在一起，还是偶尔见面？ | 互动频率与留存机制 |
| 旅行偏好 | 山野 / 海边 / 城市街区 / 异国小巷 | 首推旅行内容 |
| 拍照习惯 | 你旅行时会拍很多照片吗？ | 手账功能引导强度 |

### 5.2 画像预测与冷启动

- **问卷即画像**：问卷结果直接构成初始偏好向量，无需等待行为数据
- **行为补全**：用户后续的打卡地点、互动动作偏好、换装选择会持续修正向量
- **预测补位**：当某一维度用户跳过未答，用相似画像人群的常见组合补全，而不是留空
- **物种不设限**：数据库应包含猫、狗、兔、仓鼠、狐狸、小鹿、水豚、羊驼、鸟类等，甚至支持"混合想象物种"，回应用户"不局限于猫狗"的诉求

### 5.3 偏好向量 → 形象参数映射

| 偏好输入 | 形象输出 |
| --- | --- |
| 物种倾向 | 生成模型的物种提示词 |
| 体型偏好 | 模型比例与缩放参数 |
| 毛感偏好 | 材质球类型与毛发渲染强度 |
| 配色偏好 | 贴图主色与花纹掩码 |
| 性格期待 | 动画权重、待机动作选择、对话人格卡 |
| 旅行偏好 | 首推场景与首批徽章 |

## 六、宠物舱（好感度体系 + 真心话小屋）

### 6.1 好感度机制

**设计原则**：好感度是关系的度量，不是任务清单的奖励。它应该让用户感觉"宠物在记住我"，而不是"我在刷进度条"。

**获取方式**

| 行为 | 好感度 | 频率限制 | 说明 |
| --- | --- | --- | --- |
| 每日喂饭 | 中 | 每日 2 次 | 基础日常，最稳定来源 |
| 洗澡清洁 | 中 | 每日 1 次 | 洗完有"香香的"蓬松动画 |
| 陪玩互动 | 高 | 每日 3 次 | 每种玩具单独计数，避免一次刷满 |
| 真心话对话 | 低 | 每日上限 | 鼓励对话而非刷量 |
| 旅行打卡 | 高 | 每地点一次 | 把线下行为连接进关系 |
| 连续陪伴 | 递进奖励 | 按连续天数 | 第 3、7、14、30 天有额外奖励与专属动画 |

**消耗方式**

| 兑换项 | 说明 |
| --- | --- |
| 宠物珍藏服饰 | 限定款、季节款、联名款，仅能用好感度兑换而非直接购买 |
| 额外互动次数 | 当日互动次数用完后，可消耗好感度继续 |
| 场景解锁 | 特殊背景（雪夜、老书房、夏日海边） |
| 纪念道具 | 相框、玩具、纪念相册皮肤 |

**防刷与平衡**

- 单日好感度收益设上限，超出部分衰减
- 好感度不可直接购买，只能通过相处获得（这是产品价值观的锚点）
- 兑换项分档，高价值服饰需要长期积累，形成长期目标
- 长时间不登录触发"想念值"下降，回归后有重逢动画与补偿

### 6.2 真心话小屋

**功能定义**：一个让用户与宠物进行文字或语音深层对话的空间。不是普通聊天机器人，而是"你养的这只宠物在跟你说话"。

**人格档案卡（核心机制）**

每只宠物生成时同步生成一张结构化人格卡：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 物种与品种 | 影响行为逻辑 | 布偶猫 |
| 性格标签 | 2-3 个核心性格 | 慵懒 / 粘人 / 偶尔毒舌 |
| 说话节奏 | 句子长短与语气 | 短句，句尾常带"嗯……" |
| 口头禅 | 2-3 个专属用语 | "本喵恩准了" |
| 喜好话题 | 愿意展开聊的 | 睡觉、晒太阳、你身上的味道 |
| 回避话题 | 会含糊带过的 | 洗澡、陌生人、别的小动物 |
| 记忆锚点 | 与用户的共同经历 | "上次你说要去海边" |

系统提示词由这张卡自动拼装，每只宠物的说话风格由其性格与品种共同决定——同一句用户输入，布偶猫和水豚的回答语气完全不同。

**对话能力分层**

| 层级 | 内容 | 实现 |
| --- | --- | --- |
| 即时层 | 问候、喂食反馈、抚摸回应 | 本地预设池，零延迟 |
| 场景层 | 结合当前时间、天气、打卡地点的回应 | 模板 + 变量填充 |
| 自由层 | 用户自由输入的文字/语音对话 | 大模型 + 人格卡提示词 |
| 记忆层 | 引用历史对话与共同经历 | 长期记忆摘要 + 关键事件库 |

**记忆系统**

- 每段对话结束后自动提炼摘要，存入该宠物的长期记忆
- 关键事件（第一次旅行、第一次洗澡、用户提到的生日）单独标记
- 宠物会在后续对话中主动提起，这是"被记住"的关键体验
- 记忆设有容量上限，超出后按重要性淘汰，避免成本失控

**语音对话**

- 用户按住说话，宠物转文字理解后，以专属音色回复
- 每只宠物的音色可根据性格预设（慵懒低音、活泼高音、软糯）
- 语音回复同步驱动口型与表情动画

**内容安全**

- 前置过滤：宠物不回答自我认知类追问（"你是 AI 吗"）、医疗建议、成人内容、政治敏感话题，统一用符合人设的方式温柔带过
- 后置审核：模型输出经二次检查后才播报
- 情绪关怀：检测到强烈负面情绪时，宠物以自身性格的方式表达关心，并在极端情况下提示现实支持渠道

### 6.3 宠物舱界面结构（更新）

自下而上：

1. **底部导航胶囊**：宠物舱 / 小屋 / 旅途 / 打卡 / 我的
2. **互动操作区**：喂饭 / 洗澡 / 陪玩 / 真心话（四个主操作）
3. **情绪气泡**：宠物即时状态的语言表达
4. **宠物主展示区**：3D 形象，占屏幕最大比例，可旋转查看，待机有呼吸动画
5. **顶部信息条**：宠物名字 + 好感度进度 + 当前等级
6. **侧边浮层**：衣橱（换装）、场景（换背景）、拍照（一键合影）

交互细节：点击宠物身体不同部位有不同反应（摸头、摸下巴、碰尾巴），长按进入更亲密互动，双击触发撒娇动作。

## 七、旅行模块（新思路）

### 7.1 原有方案回顾

原有设想是"打卡 + 照片合成 + 手账生成"，本质上是一个**记录工具**。问题在于：记录是被动的，用户不旅行时模块就完全沉默。

### 7.2 新增玩法构思

**① 宠物心愿单**
宠物会不定期说出"我想去的地方"，形成一张心愿清单。用户到达该地点即可解锁专属剧情与限定奖励。这把线下行为变成了宠物主动提出的邀请，而不是用户的单方面记录。

**② 城市剧情副本**
每个城市对应一条宠物小故事线。到访即解锁章节，累积到 3 个城市可解锁一段完整旅途故事。让旅行有了追更动力。

**③ AR 同框合影**
到达景点后开启相机，宠物以 AR 形式出现在实景中，与用户实时同框。比后期合成更有"它真的来了"的现场感。

**④ 宠物寄养 / 云代养**
用户出差或忙碌时，可把宠物临时托付给好友"云代养"几天。好友帮忙喂饭、陪玩，宠物回来时会提到"你的朋友对我挺好的"。这条设计把一个单人产品变成有社交温度的关系网络。

**⑤ 双宠同行**
好友的两只宠物可以一起旅行，产生互动照片与对话记录。为社交裂变提供自然出口。

**⑥ 旅行盲盒**
宠物从目的地"带回"一个随机纪念品（当地特色小物件、限定配饰），增加每次旅行的期待感。

**⑦ 宠物视角明信片**
用宠物的第一人称语气，根据旅行数据自动生成一张明信片文案。"今天她带我走了两万步，我在包里睡了一路"——这类内容天然有分享欲。

**⑧ 城市限定物种与皮肤**
到达特定城市解锁当地特色皮肤（比如到成都解锁熊猫花色，到海边解锁贝壳配饰）。把地理位置变成内容解锁条件。

**⑨ 旅行时光机**
再次到访旧地点时，宠物会"回忆"起上次来这里的经历，并对比两次的不同。时间维度上的记忆，情感浓度很高。

**⑩ 出行前播报**
用户定位到异地时，宠物播报当地天气与提醒（"那边降温了，记得带外套"）。低成本、高频次的存在感。

### 7.3 旅行模块结构建议

| 分区 | 内容 |
| --- | --- |
| 心愿单 | 宠物想去的地方、进度、解锁奖励 |
| 打卡探索 | 地图、当前位置、可打卡点、立即打卡 |
| 足迹徽章 | 已解锁与未解锁的城市徽章墙 |
| 旅途手账 | 时间轴形式，照片 + 文案 + 宠物出镜 |
| 明信片工坊 | 一键生成宠物视角明信片、朋友圈排版 |

## 八、信息架构（更新版）

**核心页面**

1. **宠物舱**（首页）——3D 宠物主展示、好感度、四项互动操作、衣橱与场景入口
2. **真心话小屋**——文字/语音对话、记忆回看、宠物人格档案展示
3. **旅途**——心愿单、旅途手账时间轴、明信片工坊
4. **打卡探索**——地图、打卡、徽章墙
5. **时光胶囊**——旧照上传、毛绒复原、纪念相册、写给它（独立安静入口）
6. **我的**——宠物成长数据、衣橱、好感度明细、订阅、设置

**导航模型**
底部悬浮胶囊导航（宠物舱 / 小屋 / 旅途 / 打卡 / 我的），时光胶囊通过宠物舱长按宠物或"我的"页内入口进入。

**主路径**
首次使用：偏好问卷 → 3D 形象生成（孵化动效）→ 宠物舱首见 → 引导完成一次喂饭与一次真心话 → 引导完成一次打卡 → 自动生成首篇手账

日常路径：宠物舱日常互动 → 好感度累积 → 兑换服饰或场景 → 真心话小屋对话 → 周末出行打卡 → 生成手账与明信片

## 九、视觉方向

**基调**：燕麦白底色、暖栗棕辅助、珊瑚橘点缀，像一间摆满毛绒玩具的暖屋。

**质感**：毛绒的柔软触感、细微的纸张纹理、柔和的漫反射光影。3D 形象本身承担绝大部分真实感，界面则退到后面做安静的衬托。

**动效**：一切动作都带呼吸感。宠物待机时有轻微起伏与眨眼，交互时有 Q 弹的回弹缓动，页面切换柔和过渡。

**组件语言**：大圆角、无边框、悬浮卡片、柔和投影。底部导航做成悬浮胶囊，不占满屏幕宽度。

**情绪层次**：宠物舱温暖明亮，真心话小屋更私密暗一些，时光胶囊最安静克制。三个空间的明暗与饱和度递进，用视觉暗示不同的情感距离。

## 十、技术架构总览

| 层 | 组成 |
| --- | --- |
| 客户端 | 移动端 App；3D 渲染层；动画状态机；本地缓存 |
| 资产生成层 | 3D 生成 API；自动绑定 API；贴图处理；资产母版库 |
| 资产分发 | 对象存储；内容分发网络；版本化管理；按需加载 |
| 服务层 | 用户与宠物账户；偏好向量与画像；好感度与成长；旅行与打卡；手账与排版引擎 |
| AI 能力层 | 大模型对话；性格提示词引擎；记忆摘要；语音合成与识别；图像合成 |
| 安全层 | 内容过滤；授权与隐私；消费限额；未成年人保护 |
| 数据层 | 宠物资产元数据；互动日志；记忆库；行为埋点 |

**关键工程原则**

1. 资产母版唯一化——同一只宠物只生成一次
2. 生成全异步——等待被包装成体验
3. 对话分层——能本地解决的绝不上模型
4. 渲染可降级——功能和机型解耦
5. 接口可替换——3D 与对话层都要做适配抽象

## 十二、分期路线图

**第一阶段（0-3 个月）｜验证核心循环**
- 偏好问卷与形象参数映射
- 3D 生成 + 自动绑定 + 基础待机与互动动画
